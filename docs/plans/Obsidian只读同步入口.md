# Obsidian只读同步入口

## 状态与优先级

- 状态：方案已记录，暂未开始设计和实施。
- 优先级：排在当前“旧知识库质量复核”收尾之后。
- 前置工作：旧知识库质量复核中的D06、D13-D15，需要在浏览器连接恢复并重新完成只读预检后继续处理。

## 背景

用户在Obsidian中持续积累笔记，希望FlowPilot能够发现新内容或内容变化，但不希望系统未经确认就自动读取更多目录、自动导入、覆盖旧知识或删除任何资产。

本功能定位为一个“只读同步入口”：系统只扫描用户明确授权的Obsidian文件夹，生成待导入清单；最终是否导入、采用哪种保存方式，仍由用户决定。

## 核心方向

定期扫描用户授权的Obsidian文件夹，检测新增或修改的笔记，生成待导入确认清单。用户逐条确认，也可以批量确认一批内容，但批量确认不能跳过每篇笔记各自的全库查重、基础质量检查及“内容适配与完整度提示”。

确认导入后，直接复用FlowPilot已经建立的能力：

- 全库查重与基础质量检查；
- AI提炼方法卡的智能入库流程；
- 不调用AI、逐字保存的原文保真入口；
- 严格写入、失败可感知、回读确认和幂等保护。

本功能不新建另一套知识保存逻辑，也不改变现有知识的可信度规则。

## 用户流程

```text
Obsidian笔记
→ 检测到新增或修改
→ 生成待导入候选
→ 对每篇候选执行全库查重和基础质量检查
→ 生成“内容适配与完整度提示”
→ 展示完全相同／高度相似／部分相似三档结果
→ 展示与知识库中哪条内容相似、相似在哪里、来源是什么
→ 展示内容类型、完整度、建议结果和判断依据
→ 用户决定继续导入或暂不导入
→ 用户选择“AI提炼方法卡”或“原文保真保存”
→ 严格保存并回读确认
→ 成功后记录“来源：Obsidian同步”及同步凭据
```

页面提示示例：

> 检测到3篇新增或修改的笔记。系统已分别完成全库查重、基础质量检查及内容适配与完整度提示，请确认是否导入。

## 产品边界

### 1. 授权范围与只读原则

- 只扫描用户明确选择并授权的文件夹，不默认扫描整个电脑或其他Obsidian仓库。
- 扫描范围必须限制在授权目录内，不能通过软链接、相对路径或配置错误越界读取其他目录。
- 第一期仅支持Markdown和纯文本文件，主要是`.md`和`.txt`。
- 不读取或导入图片、音频、视频、PDF及其他附件。
- Obsidian的图片引用、双向链接、嵌入块等复杂语法，第一期只作为原文文本保留，不自动解析成独立知识资产。
- 扫描过程不修改Obsidian文件，不写入frontmatter，不创建标记文件，也不移动或删除笔记。
- 扫描、变更识别和确定性查重阶段不调用AI。只有用户明确选择“AI提炼方法卡”后，才进入现有AI入库流程。

### 2. 新增、修改与移动识别

- 使用授权仓库标识、相对路径、内容哈希和文件修改信息建立本地变更索引。
- 内容哈希未变化时，不因重复扫描而反复提醒。
- 新路径下出现与已索引笔记完全相同的内容时，应优先识别为可能的改名或移动，不直接当成新笔记。
- 文件同时改名和修改、无法可靠判断身份时，应进入人工确认，不能擅自建立或合并关系。
- frontmatter中的标题、标签等信息可以作为展示辅助，但不能单独作为笔记身份或内容一致性的依据。
- 索引只用于判断同步状态，不能被当作知识已成功入库的证明。

### 3. 修改笔记的处理

- 已经导入过的笔记发生修改时，必须展示上次导入内容与当前内容的差异。
- 不能直接覆盖既有知识，也不能因为文件内容变化就自动新增一条知识。
- 用户可选择：暂不处理、作为新版本导入，或进入以后单独设计的安全更新流程。
- 第一期优先支持“暂不处理”和“作为新版本导入”；若现有入口不具备可靠的版本更新能力，不扩大范围实现直接覆盖。
- 保存新版本时要保留它与原笔记、旧知识之间的来源关系，避免形成无法追溯的重复条目。

### 4. 删除笔记的处理

- Obsidian中的笔记被删除、移出授权目录或暂时不可读取时，只更新同步状态。
- 不自动删除、隐藏或修改已经进入FlowPilot知识库的内容。
- 如果未来需要清理对应知识，必须走独立的备份、引用检查、人工确认和可恢复删除流程。

### 5. 全库查重、基础质量与内容适配提示

- 查重范围是整个知识库，不只比较本次扫描批次。
- 复用现有三档相似度契约：完全相同、高度相似、部分相似。
- 每条结果必须展示相似知识的标题、分类、所属IP或通用归属、来源及相似原因。
- 相似原因必须说明真实比较依据，例如正文相似、核心方法相似或结构字段相似，不能伪造不存在的结构证据。
- 系统只提供判断依据，不自动合并、覆盖、删除或跳过笔记。
- 基础质量检查只提示需要人工检查，例如内容为空或过少、几乎全是符号、大量重复、关键部分缺失、疑似截断。
- 质量提示不能自动等同于“无效”或“不值得入库”。

在全库查重和基础质量检查之外，增加“内容适配与完整度提示”。该提示只判断笔记表面的内容类型和成熟度，是基础质量提示的增强，不等同于基于真实效果数据的“入库价值判断”。真正的入库价值判断仍依赖知识效果追踪、人工复盘及真实发布效果数据。

每篇候选应展示：

- 内容类型：方法论总结／临时想法或草稿／日常记录或无关内容／无法确定；
- 完整度：完整／缺少核心方法／缺少适用场景／仅标题或碎片；
- 建议结果：建议导入／建议人工复核／建议暂不导入；
- 判断依据：说明系统为什么给出该内容类型、完整度和建议结果；
- 用户操作：继续导入／暂不导入，始终需要用户主动点击确认。

提示规则：

- “方法论总结”可以提示“建议导入”，但不能自动确认或直接进入保存；
- “临时想法或草稿”“日常记录或无关内容”可以提示“建议人工复核”或“建议暂不导入”，但不能强制拦截；
- “无法确定”必须如实展示，不得为了给出确定答案而猜测分类；
- 完整度检查重点确认是否说清楚核心方法和适用场景，以及内容是否仅为标题、一句话或碎片；
- 任何提示都只提供判断依据，不能自动导入、自动拒绝、自动修改可信度或替用户作出最终决定。

### 6. 待导入确认清单

- 清单分别标明新增笔记、已修改笔记和身份无法确认的笔记。
- 每篇笔记独立展示查重结果、基础质量提示、内容适配与完整度提示、来源路径和最近修改时间。
- 用户可以逐条确认，也可以勾选多篇后批量确认。
- 批量确认只减少重复点击，不能跳过任何一篇笔记的查重、质量检查和结果生成。
- 完全相同的内容也只提示，由用户决定是否继续导入，不自动拦截或合并。
- “暂不导入”不等于永久忽略。是否再次提醒应由明确的忽略状态或内容再次变化决定。

### 7. 保存入口与可靠性

- 用户确认后，必须明确选择“AI提炼方法卡”或“原文保真保存”。
- AI提炼方法卡复用现有智能入库流程及其可信度、查重和保存规则。
- 原文保真保存复用现有模板身份、版本、正文哈希、不可篡改和另存新版规则。
- 页面层不自行拼装存储操作，统一调用现有可靠保存入口。
- 保存必须严格写入并回读确认；失败时明确提示，允许重试。
- 只有保存和回读都成功后，才能把该笔记标记为已导入。
- 重复点击或失败后重试不得制造重复知识或孤立数据。

### 8. 来源与同步凭据

成功入库后，知识条目应记录：

- 来源类型：Obsidian同步；
- Obsidian仓库或授权目录的本地标识；
- 原文件相对路径；
- 导入时的内容哈希；
- 导入时间；
- 选择的保存方式；
- 如为修改后的新版本，记录前一版本或原知识的关联。

本地绝对路径可能包含用户名或私人目录信息，页面展示和对外导出时应优先使用授权目录名称和相对路径，避免无必要地暴露完整电脑路径。

“来源：Obsidian同步”只说明内容从哪里进入系统，不代表内容已经被验证有效，也不自动提升可信度。

### 9. 人工决策与可信度边界

- 系统不根据笔记标题、文件夹位置或Obsidian标签自动判断知识有效性。
- 用户确认导入只代表允许保存，不等于“人工确认有效”。
- AI提炼产生的方法卡继续遵循现有可信度体系，不能在入库时冒充已验证知识。
- 原文保真保存只证明正文被逐字保存，不证明内容观点正确。
- 是否有效仍应结合知识采用记录、发布复盘和真实效果证据，由用户后续判断。
- 内容适配与完整度提示只判断表面成熟度，不得被展示或保存为“知识有效”“方法有效”或“值得长期保留”的结论。
- AI原始判断和用户最终决定必须分别保存，不能相互覆盖；修改记录应能说明用户是接受、修改还是拒绝了AI建议。
- 系统不根据用户的确认、修改或删除行为自动学习其习惯，也不自动调整以后对其他笔记的分类和建议逻辑。

### 10. 隐私与安全

- Obsidian笔记可能包含私人记录、账号信息、客户资料或其他敏感内容，授权页面必须明确展示扫描目录和支持的文件类型。
- 不扫描隐藏目录、回收站、插件缓存和Obsidian内部配置目录，除非未来有明确、单独的产品设计。
- 未经用户明确授权，不得把整篇Obsidian笔记发送给外部AI或其他外部服务。
- 授权页面必须清楚说明会读取哪些目录、哪些文件类型、分析哪些内容、是否会调用外部AI，以及调用时会发送哪些正文。
- 内容适配与完整度提示如需调用外部AI，必须在分析前单独取得明确授权；未授权时只能使用不外发正文的本地或确定性检查，并如实说明能力限制。
- 用户后续选择“AI提炼方法卡”时，仍应按现有流程再次明确提示AI调用范围，不能把之前的目录扫描授权自动扩大为正文外发授权。
- 日志和错误提示不得记录完整敏感正文，只保留必要的文件标识、哈希和错误类型。
- 用户撤销目录授权后应停止后续扫描，但不能自动删除已经导入的知识或历史审计记录。

## 第一期拆分

### 提交1：只读扫描与变更索引

目标：安全识别授权目录内的新增和修改笔记，不接入知识保存。

范围：

- 用户选择并授权Obsidian文件夹；
- 只读扫描`.md`和`.txt`文件；
- 建立本地变更索引；
- 识别新增、修改、未变化和可能移动的笔记；
- 无越界读取，不调用AI，不修改Obsidian或知识库。

重点验证：

- 未授权目录不可读取；
- 重复扫描不重复产生候选；
- 文件改名或移动不会轻易变成重复候选；
- 损坏文件、权限失败和编码异常能安全提示，不阻断其他笔记扫描；
- 页面渲染不触发扫描或索引维护写入，扫描由明确动作或受控计划触发。

### 提交2：待导入确认清单

目标：让用户看懂每篇候选与现有知识的关系，再作决定。

范围：

- 展示新增、修改和身份待确认的候选；
- 对每篇笔记运行全库查重、基础质量检查及内容适配与完整度提示；
- 展示三档相似度、相似条目、来源和相似原因；
- 展示内容类型、完整度、建议结果和判断依据；
- 保存AI原始判断、用户最终决定及必要的修改记录，二者互不覆盖；
- 展示修改前后差异；
- 支持逐条确认和批量勾选确认，但不跳过单条检查；
- 不执行任何自动合并、覆盖、删除或入库。

重点验证：

- 跨全库检索而非批次内比较；
- 相似原因与真实比较字段一致；
- 检查失败能明确提示并重试；
- “方法论总结”不会自动确认导入，“草稿”或“无关内容”也不会被强制拒绝；
- 内容类型无法确定时如实降级，不伪造确定结论；
- 用户修改或拒绝AI建议后，AI原始判断仍可追溯，系统不自动学习该行为；
- 未取得正文外发授权时，不会把整篇笔记发送给外部AI；
- 批量操作不会把未完成检查的笔记带入保存流程；
- 没有当前IP时不泄露任何私有知识，查重使用明确的“全库比较”能力，浏览和展示仍遵守IP隔离规则。

### 提交3：接入现有两种保存入口

目标：将人工确认后的候选安全交给现有入库能力。

范围：

- 接入AI提炼方法卡；
- 接入原文保真保存；
- 成功后写入Obsidian来源和同步凭据；
- 严格写入、回读确认、幂等保护、失败重试；
- 导入成功后更新候选状态；
- 不新建第三套保存逻辑。

重点验证：

- 全程只在用户确认后调用保存入口；
- 原文保真模式不调用AI；
- AI模式沿用现有可信度规则；
- 保存失败不会误显示成功；
- 回读失败不会把候选标记为已导入；
- 重试和重复点击不会制造重复知识；
- Obsidian文件本身始终没有被写入或修改。

## 第一期明确不做

- 不实时监听每一次文件编辑；
- 不自动导入；
- 不自动更新或覆盖旧知识；
- 不自动删除知识；
- 不自动解析图片、音频、视频、PDF或Obsidian附件；
- 不把双向链接自动建设成知识图谱；
- 不根据用户修改习惯自动学习分类或可信度；
- 不实现跨设备Obsidian同步；
- 不替代Obsidian自身的版本管理和备份能力。

## 后续设计前需要确认

1. 定期扫描采用用户手动触发、应用启动后提示，还是可配置的本地计划任务；任何后台扫描都必须可关闭并清楚显示最近扫描时间。
2. 一个用户是否允许授权多个Obsidian仓库，以及如何展示不同仓库的同名路径。
3. 修改笔记除“另存新版本”外，是否需要新增受控的知识更新入口。
4. 批量确认的数量上限及失败时的逐条结果反馈方式。
5. 内容适配与完整度提示优先采用本地确定性规则，还是允许用户单独授权外部AI分析；两种模式的能力差异如何展示。
6. 用户选择AI提炼时，敏感内容提示和AI调用范围如何展示。

## 验收原则

第一期完成后，应满足：系统能在不修改Obsidian的前提下发现新增或修改笔记；每篇笔记都经过全库查重、基础质量检查及内容适配与完整度提示；用户能看懂相似内容、表面成熟度、建议及原因并自主决定；AI原始判断和用户最终决定分别保留且不被用于自动学习；未经明确授权不向外部AI发送整篇笔记；确认后复用现有可靠入口保存；任何失败、重复或历史数据异常都不会被静默掩盖。
