## 一、共同前提

1. 正式知识、生命周期账本、演进线、账本头部和必要幂等状态共同构成真相快照。
2. 知识与账本不得分别恢复、分别合并或分别宣称成功。
3. 版本化密钥环使用独立安全载体，不进入普通业务备份；密钥环未恢复时，历史凭证验证不得判定通过。
4. 备份格式必须在路线B最终存储模型确定后另行锁定，本记录不提前决定JSON、压缩包或分片文件结构。

## 二、W19备份恢复目标语义

### 2.1正式裁定

W19恢复是一项带操作编号的独立整体事务。恢复目标不是“把若干键写回去”，而是形成一份经过验证的完整真相快照。

恢复流程必须：

1. 在事务开始前预检备份版本、知识、事件、演进线、账本头部、哈希链、操作记录和凭证密钥版本引用；
2. 在同一个IndexedDB读写事务内写入正式知识、完整账本、演进关系、账本头部和必要幂等状态；
3. 任一必要组成缺失、缺片、错序、哈希错误或版本不兼容时，中止事务，不改变恢复前真相源；
4. 事务提交后使用独立只读事务执行《恢复能力依赖清单》第八章八项核对；
5. 八项核对任一失败时进入损坏冻结，不得进入可写状态，不得伪装成恢复成功；
6. 恢复成功不等于立即删除旧真相源或备份文件，清理需要独立人工授权。

### 2.2冲突处理

- 目标环境为空且备份完整：允许进入恢复事务。
- 目标环境已有真相源：不得自动覆盖或逐条合并，必须停止并要求用户明确选择独立恢复环境或执行经过审查的整体替换流程。
- 操作编号相同且内容相同：按真实事务状态返回既有结果或恢复未完成事务。
- 操作编号相同但内容不同：拒绝，按E03处理。
- 目标真相源版本已变化：拒绝陈旧恢复请求，不自动选边。

### 2.3防什么

- 防止只恢复知识、不恢复账本；
- 防止逐键写入产生半恢复；
- 防止损坏备份进入可写状态；
- 防止失败恢复覆盖现有真相源。

### 2.4不防什么

- 不证明备份里的业务内容本身正确；
- 不保证独立密钥环载体已经存在；
- 不处理远端权限、传输安全和保留期限；
- 不决定最终备份文件格式。

## 三、W20本地同步目标语义

### 3.1正式裁定

第一期W20的同步单位裁定为：**来自同一个受信版本的完整真相快照，目标仅作为非权威只读镜像。**

具体语义：

1. 同步导出必须从一个一致版本读取正式知识、完整账本、演进关系、账本头部和必要幂等状态；
2. 同步目标不得成为第二个可写真相源，不得反向增量合并回本地真相源；
3. 若需要把同步镜像重新写回系统，必须进入W19完整恢复事务，不得沿用旧的按键合并逻辑；
4. 同步不得补造、改写或删除生命周期事件；
5. 同步失败只影响镜像更新，不改变当前本地真相源；
6. 当前`LocalDataSync`若只覆盖部分localStorage键，不得宣称已经完成W20目标语义。

### 3.2冲突处理

- 镜像目标不存在：写入新的完整只读快照。
- 镜像目标版本与当前真相源一致：允许幂等返回或覆盖同版本镜像。
- 镜像目标版本、账本头部或演进线与当前真相源不一致：停止同步并记录冲突，不自动选择任一侧。
- 任何“知识较新但账本较旧”或“账本较新但知识较旧”的组合：视为不完整快照，不得发布为有效镜像。
- 禁止逐条合并知识、拼接事件数组或用更新时间决定真相。

### 3.3防什么

- 防止本地同步制造第二条真相链；
- 防止知识和账本分别更新；
- 防止旧镜像自动覆盖当前真相源；
- 防止同步过程补造生命周期事件。

### 3.4不防什么

- 不提供多人协作或跨设备并发编辑；
- 不保证镜像存储介质可靠；
- 不等于业务恢复已经通过八项核对；
- 不授权现有LocalDataSync直接接管路线B数据。
